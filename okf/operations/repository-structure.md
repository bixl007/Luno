# Rules

* **`app/` holds routes only.** Pages and route handlers stay thin and import from `components/` and `lib/`. UI components do not live under `app/`.
* **`lib/` is split by concern**, not by file type: `ai/` (model, prompt, search, titles), `db/`, `http/`. A new concern gets a new folder; do not add a catch-all `utils`.
* **Dependency direction:** `app` → `components`, `lib`. `components` → `lib/http` and `components/ui`. Inside `lib/ai`: `reply` → `gemini`, `prompt`, `webSearch`, `needsSearch`; `title` and `webSearch` → `gemini`; `gemini` imports nothing from the other files. `lib/ai` may import types from `lib/http`. `lib` never imports from `components` or `app`.
* **Imports use the `@/` alias** (`@/lib/ai/reply`), never `../../`, except for a sibling in the same folder.
* **Server-only code** (`lib/ai`, `lib/db`) is never imported by a client component. `lib/http/ndjson.ts` is the one shared module and is safe in both places.
* **Tests mirror the source tree** under `tests/`, see [testing](/operations/testing.md). Tests are not placed next to source files.

# Where does new code go?

| Adding | Put it in |
|--------|-----------|
| A new endpoint | `src/app/api/<name>/route.ts`, logic in `src/lib/` |
| A model or search feature | `src/lib/ai/` (and a concept in `okf/ai/`) |
| A table or query helper | `prisma/schema.prisma` with a migration, helpers in `src/lib/db/` |
| A chat UI piece | `src/components/chat/` |
| A reusable visual block | `src/components/ui/` |
| A test | the matching folder under `tests/` |
